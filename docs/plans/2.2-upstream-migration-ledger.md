# Caliptra 2.2 upstream migration ledger

Initial snapshot: November 13, 2026. Companion: [migration plan](2.2-upstream-migration-plan.md).

This is the working record for integrating 2.2 development and publishing reviewed changes to `main-2.1` after the 2.1 release freeze. Updating this ledger does not authorize implementation, branch rewrites, merges, or changes to repository settings.

## Status and ownership rules

- **Present in dev** means the change is already integrated in `caliptra-mcu-dev-2.2`; it does not mean published to main.
- **Refresh needed** means an existing publication or USB PR must be reconciled with current source and retested.
- **Unverified** means the required acceptance evidence has not been recorded. It is not a pass.
- **Hold** means intentionally outside the current production publication path.
- Dependencies refer to the IDs below. They are the proposed execution constraints, not proof that existing PR bases are correct.
- Owners/reviewers are proposed coordination contacts, not assignments already accepted.
- A green CI rollup is only an observation. Verify actual required contexts, final candidate SHA, hardware selection, and test coverage before marking any row ready.

**Initial readiness: no publication row is marked ready to merge.** The 2.1 release gate remains closed pending explicit release-owner approval.

## G. Acceptance and publication log

Active main requirements at initial capture: `precheckin`, `test_emulator (1)` through `(8)`, `test_artifacts`, `test_spdm`, and one approving review. Re-read the active rules before each publication batch.

Dual-revision matrices must not accidentally remove those contexts. A gate cannot report success when its required underlying jobs fail, are cancelled, or never run. Current FPGA artifact/SPDM execution is 2.1-only; latest FPGA execution requires separate evidence.

For each ready candidate, append a row:

| Unit | Final candidate SHA / base SHA | Tested 2.1 Core + RTL | Tested latest Core + RTL | CI run URLs / required contexts | Local/targeted evidence | Approval | Main PR / merged SHA |
|---|---|---|---|---|---|---|---|
| No accepted publication candidate recorded | Unverified | Unverified | Unverified | Unverified | E1 applies only to B2 | Pending | None |

Before marking a unit ready:

- Record its actual final head and base, not an earlier stack tip.
- Verify required contexts succeed and the reviewer approves.
- Run both revision precheckins with matching pins, deterministic generated-file checks, and relevant regressions for the reconstructed candidate.
- Preserve main's release fixes and compatibility coverage; confirm no USB behavior leaks into 2.1.
- For privileged or hardware claims, verify prerequisites and actual execution; a skipped test is not a pass.
- After a parent merges or the base changes, refresh the child and record fresh acceptance evidence.
- After publication, record the main merged SHA, source disposition, and reviewed reconciliation back into development.
